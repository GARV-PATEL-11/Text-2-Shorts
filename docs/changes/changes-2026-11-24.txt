PART 1 — the outline stage and the prompts package
---------------------------------------------------

001 [RESTORED] app/outline_models/ (base_outline.py, conceptual_zoom.py, problem_solution_arc.py,
    classic_linear_narrative.py, __init__.py)
    The four model files removed in 0.7.0 are back, unchanged except the base file's docstring, which now names
    the file correctly (base_outline.py, not base_models.py). They validate outline.json again.

002 [ADDED] app/outline_models/base_outline.py — `VideoOutline`
    A root model for the creative approach: the shared meta and segments without approach-specific rules, so every
    one of the four approaches has a model.

003 [ADDED] run-environment/prompts/script_prompts/ (from the supplied package)
    The refactored prompts: req_modifier.py, classic_linear_narrative.py, problem_to_solution_arc.py,
    conceptual_zoom.py, _shared.py and __init__.py, placed in the run environment (not app/, which holds no
    prompts). req_modifier.py includes the user's edit: the length is the user's, not a fixed 5–6 minutes.

004 [ADDED] run-environment/prompts/export_references.py
    Renders each prompt as a Markdown reference the run session reads by path, with a short note on how to use it
    in a run; the prompts stay maintained once, in the package.

005 [ADDED] references/topic-list.md, outline-linear.md, outline-arc.md, outline-zoom.md (generated)
    The request-modifier prompt and the three outline prompts, as the session's stage-1 and stage-2 guidance.

006 [ADDED] tests/test_run_environment.py — drift test for the generated references
    Fails when a reference no longer matches the package (it caught the req_modifier.py edit, re-exported); also
    checks the topic prompt keeps its single {user_raw_input} placeholder.

007 [ADDED] app/run_steps.py — `validate_topics()` and `validate_content()`
    topics.md must be a numbered list 1., 2., 3. …; content.md must have one non-empty `## <topic>` section per
    topic, in the list's order. content.md is the outline's raw_content (the gap the package's notes pointed out).

008 [ADDED] app/run_steps.py — `validate_outline()`
    outline.json is validated by the approach's model (OUTLINE_MODELS) and the prompts' checkable rules: segment
    order A2/B2/C2, first segment A7/B3, zoom ends with a recap (C2), 10–120 s per segment (G2), transition only
    missing on the last segment (S13), visual plan sentence count (VP2), empty-canvas opening (VP3), "The scene
    ends with" closing (VP4), no double quotes (VP5).

009 [ADDED] app/run_steps.py — CP0 (`approve <run> outline`)
    An outline fingerprint joins the stage approvals; approving the outline also checks topics.md and content.md.
    Editing an approved outline makes CP0 stale.

010 [ADDED] schemas/models.py — `ScriptScene.outline_segment`
    Which outline segment a script scene narrates; `validate_script()` requires the scenes after the index to
    narrate every segment once, in order, and refuses any script before CP0.

011 [MODIFIED] app/run_steps.py — status and `next` include the new stages
    Brief → topics.md → content.md → outline.json → CP0 → script …; stage labels renumbered (1 requirements,
    2 outline, 3 script, 4 plans, 5 production). The hook and `validate` cover topics, content and outline.


PART 2 — change requests, checkpoint decisions, standing preferences
---------------------------------------------------------------------

012 [ADDED] schemas/models.py — `ChangeRequest` and `RequestResolution`
    A tweak the user asked for: id rNNN, target (outline, script, plan, final, sNN, sNNcMM), kind (wording, visual,
    audio-timing, accuracy, structure, style, other), the user's words, the checkpoint it was raised at; and how it
    was resolved (applied or declined, with a note).

013 [MODIFIED] app/run_steps.py — `text-2-shorts feedback` records validated change requests
    `--kind` replaces `--scope`; `--checkpoint` also records the decision "changes requested". Requests and
    resolutions are append-only events in requests.jsonl (feedback.jsonl is gone).

014 [ADDED] app/run_steps.py — `text-2-shorts resolve <run> rNNN applied|declined [--note]`
    Closes a request; status shows every open request.

015 [ADDED] app/run_steps.py — open requests block their checkpoint (`blocking_requests()`)
    A structure request blocks CP0, wording/accuracy requests block CP1, scene-level visual requests block CP2,
    any request on a scene blocks its CP3, and any open request blocks CP4 (all forceable by the user).

016 [ADDED] app/run_steps.py — `next` routes open requests (`request_route()`)
    Each open request becomes an action at the artifact it changes (outline.json, script.json, a scene plan,
    preferences.json, the audio-refactorer, or a question to the user), with the `resolve` command to run after.

017 [ADDED] app/run_steps.py — a clip's requests resolve when it is rebuilt (`resolve_clip_requests()`)
    After a clip passes `accept`, its open requests (except audio timing) are marked applied with the time.

018 [ADDED] schemas/models.py, app/run_steps.py — `CheckpointDecision` and decisions.jsonl
    Every approval is recorded (approved, approved with notes via `approve --notes`, forced flagged, with the
    approved fingerprint), as is every change requested at a checkpoint.

019 [ADDED] schemas/models.py — `Preferences` (preferences.json)
    Standing settings: tone, palette roles, background, font, voice rate (80–120%), pause length (200–2000 ms),
    confirm each scene; validated by the hook and `validate . preferences`.

020 [ADDED] app/run_steps.py — preferences applied at every stage
    `video_style()` and `video_font()` feed the clip key, TASK.md (palette roles line) and the render background;
    `clip_speech()` applies the pause length and voice rate to the SSML the voice speaks (re-voicing when changed).

021 [ADDED] app/run_steps.py — confirm each scene (`approve <run> start:sNN`)
    With confirm_each_scene on, `next` asks the user before a scene's production starts.

022 [ADDED] app/cli.py — preferences carry into new runs
    `text-2-shorts new` copies preferences.json from the repository root into the run, if it exists.

023 [MODIFIED] app/narration.py — `speakable_ssml(..., pause_ms)`
    The [pause] length is a parameter, so preferences can change it.

---------------------------------------------------------------------------------------------------------

on requested changes) · 6 the clip-level loop is the per-scene video critic · 2, 4, 5 not decided, kept as they are

037 [MODIFIED] app/run_steps.py — `prepare_clip()`: clips are built one at a time, in order
    A clip's task is refused ("build sNNcMM first") until every earlier clip of its scene is accepted for its
    current inputs; the accepted earlier clips are copied into work/clip_MM/scene/clips/, so the clip starts from
    their real end state. Replaces 0.9.0's "clips are independent".

038 [MODIFIED] app/run_steps.py — `next_actions()` hands out one clip-builder action (parallel false)
    The first unbuilt clip of the current scene; the next one comes after `accept`.

039 [REMOVED] app/run_steps.py — the script critic loop before CP1
    The driver no longer runs the script-critic up to 3 times before every CP1.

040 [ADDED] app/run_steps.py — `script_changes_requested()`, `script_critique_problems()`
    Each "changes requested" decision at the script checkpoint buys exactly one script-critic round. Until it is
    written, `next` dispatches the critic before routing the request to the refactor, and CP1 is blocked; more
    rounds than requests is a validation error. Without requests no critique is needed.

041 [ADDED] schemas/models.py — `CritiqueRound.score` (0–100)
    Plan and video rounds must carry it; the verdict must follow the threshold (pass iff score ≥ threshold).
