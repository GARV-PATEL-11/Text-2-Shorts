PART 1 — 0.7.0: requirements → complete script → scene visual plans → clip code, enforced in order
--------------------------------------------------------------------------------------------------

001 [MODIFIED] schemas/models.py — `Brief`
    The unused `Brief` model was reshaped to match the brief.json that `text-2-shorts new` really writes
    (requirement, audience, approach, minutes, pace, notes, tts, voice, engine, font) and gained `objectives`
    and `style`. It is now the contract for stage 1 and is validated.

002 [ADDED] app/cli.py — `--objective` and `--style` flags
    `text-2-shorts new` accepts `--objective` (repeatable: what the viewer should be able to do afterwards) and
    `--style` (explanation style, default "ELI5 / Feynman"); both are stored in brief.json.

003 [MODIFIED] app/cli.py — brief built and validated before a run is created
    New `brief_from_arguments()` assembles brief.json (including the default voice per provider); `new` checks
    it against `Brief` before creating runs/<id>, so an invalid request never produces a half-made run.

004 [MODIFIED] app/cli.py — `build_parser()` split out of `main()`
    The argument parser is built by its own function so tests can parse arguments without running a command;
    the default-voice logic moved from `main()` into `brief_from_arguments()`.

005 [ADDED] schemas/models.py — `Script` and `ScriptScene` (script.json)
    The complete script: title, structure, objectives, target words per minute and, per scene, objective, key
    concepts, covered objectives, duration, spoken bridge (`bridge_in`), complete narration and a short visual idea.
    It replaces the outline as the stage-2 artifact.

006 [REMOVED] app/outline_models/ (base_outline.py, conceptual_zoom.py, problem_solution_arc.py,
    classic_linear_narrative.py, __init__.py)
    The three outline schemas were structurally identical (only docstrings differed) and had no narration.
    One `Script` schema now serves every narrative structure.

007 [ADDED] app/run_steps.py — `validate_script()`
    Gate for script.json: every objective is covered by a scene, every brief objective appears in the script,
    each scene's spoken words fit its duration (±25% of duration × wpm), and the scenes total the requested
    length (±20%).

008 [ADDED] schemas/models.py — inter-scene bridge rule
    The `Script` validator requires an empty `bridge_in` for the first scene and a non-empty one for every later
    scene, so each scene opens by saying what was covered, what comes next and why it matters.

009 [MODIFIED] schemas/models.py — `ScenePlan`
    Added `composition` (required: zones and main visual elements) and `transition_in` (how the scene opens from
    the previous scene's final image). Removed `segment_type` and `transition_to_next`, now covered by the script.

010 [ADDED] app/run_steps.py — script-to-plan traceability check
    `validate_plan()` joins the clips' narration and requires it to equal the approved script's text for that
    scene (bridge + narration), word for word and in order. Wording can only change through the script.

011 [ADDED] app/run_steps.py — opening transition required
    `validate_plan()` rejects a plan for any scene after s01 whose `transition_in` is empty.

012 [ADDED] app/run_steps.py — stage gate before visual planning
    `validate_plan()` refuses every plan until CP1 (the script) is approved and still matches the current
    script.json (`stage_approval_problem()`, `require_approval()`).

013 [ADDED] app/run_steps.py — fingerprinted stage approvals
    `script_fingerprint()` and `plans_fingerprint()` are stored with CP1 and CP2; editing an approved script or
    plan makes its checkpoint stale automatically (`STAGE_FINGERPRINTS`).

014 [FIXED] app/run_steps.py — `is_approval_current()` with nothing to approve
    A forced approval recorded before script.json existed (fingerprint None) counted as current and opened the
    next stage. A missing fingerprint now never counts as approved (test added first).

015 [ADDED] app/run_steps.py — CP2 gates on `voice` and `task`
    `text-2-shorts voice` and `text-2-shorts task` exit with "CP2 … get CP2 first" until the scene plans are
    approved and unchanged since approval.

016 [MODIFIED] app/run_steps.py — approval targets
    `text-2-shorts approve` takes `script | plan | sNN | final` (was `outline | plan | sNN | final`); stage
    approvals store the stage fingerprint, scene and final approvals the clip fingerprint.

017 [MODIFIED] app/run_steps.py — `next_steps()` follows the stage order
    Status now lists brief → script → script review → CP1 → plans → plan review → CP2 → audio → clips → CP3 →
    final → CP4, and stops at the first stage that is not approved, so nothing downstream is suggested early.

018 [ADDED] schemas/models.py — `ReviewReport` and `ReviewFinding`
    Accuracy findings now point at a `target` (scene id or clip id) instead of only a clip id; they replace the
    `MathFinding` / `MathReport` classes that lived in app/run_steps.py.

019 [ADDED] app/run_steps.py — accuracy review at both stages
    `validate_review()` checks script_review.json (scene targets) and plan_review.json (clip targets);
    `review_problems()` makes ERROR findings block CP1/CP2. These replace math.json.

020 [MODIFIED] app/run_steps.py — accuracy notes in TASK.md
    `review_notes()` collects the findings for a clip and its scene; TASK.md shows them as "ACCURACY NOTES"
    (was "MATH NOTES" from math.json).

021 [MODIFIED] app/run_steps.py — hook validators
    The PostToolUse hook now validates brief.json, script.json, scenes/sNN/plan.json, script_review.json and
    plan_review.json the moment they are written (outline.json and math.json are gone).

022 [MODIFIED] app/run_steps.py — `validate` command and feedback guidance
    `text-2-shorts validate` takes `brief | script | script-review | plan | plan-review`; `feedback` now says
    that a wording change goes through script.json (CP1 again) and a plan change needs CP2 again.

023 [MODIFIED] app/run_steps.py — module docstring
    Describes the staged workflow (which artifact each stage writes, which checkpoint closes it) and the ledger
    files, instead of the old outline-based description.

024 [RENAMED] run-environment/agents/math-reviewer.md → accuracy-reviewer.md
    The subagent now runs in two modes: script mode (every claim in the narration, per scene, before CP1) and
    plan mode (on-screen formulas and labels, per clip, before CP2).

PART 2 — 0.8.0: index scene, creative approach, SSML, critic loops, audio follows the video, 720p30 drafts
----------------------------------------------------------------------------------------------------------

052 [MODIFIED] approaches: `custom` → `creative`
    Brief, `--approach`, narrative-structures.md, requirements.md, make-short and the produce skill now offer
    three fixed structures (zoom, arc, linear) and one creative one (designed for the topic, or the user's own).

053 [ADDED] schemas/models.py — index scene
    `ScriptScene` gained `role` (index · content · recap) and `previews`; the `Script` validator requires s01 to be
    the index scene previewing every later scene, only s01 to be an index, and every teaching scene to cover an
    objective.

054 [MODIFIED] references/script-writing.md, transitions.md, narrative-structures.md
    Rules for the index scene (hook + route ahead, 10–25 s), the bridge from the index into s02, and the creative
    structure (name it in `structure` with a one-line rationale).

055 [ADDED] schemas/models.py — `ClipPlan.ssml`
    Every clip carries its audio plan: SSML over exactly its narration words, with breaks for waits and pauses,
    prosody rate for pace, emphasis, sentence and substitution tags.

056 [ADDED] app/narration.py — SSML helpers
    `SSML_TAGS`, `ssml_problems()` (well-formed, single <speak>, allowed tags), `ssml_words()`, `speakable_ssml()`
    (symbols spoken by name inside the text, [pause] → <break>), `mark_words()` (Google word marks).

057 [REMOVED] app/narration.py — `to_ssml()` and `to_ssml_marked()`
    The text-to-SSML converters were replaced, because the SSML is now planned per clip rather than generated
    from plain narration.

058 [MODIFIED] app/narration.py — `to_plain()`
    Accepts SSML: removes tags, turns breaks into an ellipsis and unescapes entities, for voices that reject SSML.

059 [MODIFIED] app/narration.py — Polly synthesizer
    Takes the clip's SSML, removes tags the engine does not support (`UNSUPPORTED_TAGS`: emphasis for neural and
    generative) and falls back to plain text if Polly still rejects it; word speech marks unchanged.

060 [MODIFIED] app/narration.py — Google synthesizer
    Takes the clip's SSML and inserts a <mark> before every word with `mark_words()`, so word timings work with
    planned breaks and prosody; plain-text fallback for voices without SSML.

061 [MODIFIED] app/run_steps.py — `voice` and `stale_audio()`
    Audio is synthesised from the clip's speakable SSML; the voice hash covers the prepared SSML (an SSML edit
    re-synthesises only that clip); the audio index stores the spoken text as plain text.

062 [ADDED] app/run_steps.py — SSML check in `validate_plan()`
    Each clip's SSML must be well-formed, use only allowed tags and contain exactly the clip's narration words
    (only tags may be added).

063 [ADDED] schemas/models.py — `Critique`, `CritiqueRound`, `CritiqueIssue`
    One critique file per scene and kind: rounds of {reviewed version, verdict pass|revise, issues with target,
    aspect, problem, fix}; "revise" must list issues and "pass" may not.

064 [ADDED] app/run_steps.py — critic loop enforcement (3 rounds)
    `MAX_CRITIQUE_ROUNDS = 3`, `critique_subject_hash()`, `validate_critique()` and `critique_problems()`: the
    last round must have passed the current version; after round 3 the open issues are shown to the user and
    approval needs `--force`.

065 [ADDED] app/run_steps.py — CP2 requires plan critiques
    CP2 approval and status require a passing plan critique for every scene's current plan (or the user's
    acceptance after round 3).

066 [ADDED] app/run_steps.py — `hash` command and critique validation
    `text-2-shorts hash <run> sNN plan|video` prints the version a critique round records;
    `validate … plan-critique|video-critique --scene sNN`; the hook validates critique files when written.

067 [MODIFIED] app/run_steps.py — `clip_key()` no longer depends on SSML or audio
    A clip's code key excludes its SSML and audio entry, so re-timing the audio to the built video does not
    force a clip rebuild; a change of words still does.

068 [ADDED] app/run_steps.py — `scene_fingerprint()`
    A scene's clip keys plus its audio; `fingerprint()` (used by CP3 and the final render) is built from it, so
    new audio asks CP3 again and re-renders the final.

069 [MODIFIED] app/run_steps.py — `plans_fingerprint()` ignores SSML
    CP2 approves the visual plans; SSML-only edits by the audio-refactorer after CP2 do not make CP2 stale.

070 [ADDED] tools/scene_harness.py — `self.beat(n)`
    Generated scenes get a `beat(number)` method and a `beat_log`, so clip code marks where each planned beat's
    animation starts.

071 [MODIFIED] tools/layout_probe.py — beat times in the report
    The probe keeps the scene instance after rendering and reports `beats` per clip in seconds from the clip's
    start.

072 [MODIFIED] tools/validate_manim_code.py — `beat` is a known method
    `PROJECT_SCENE_METHODS = {"beat"}` stops the validator warning about `self.beat(...)` as an unknown method.

073 [ADDED] app/clip_gates.py — `BEAT_MARKS_MISSING` probe gate
    `./check probe` fails a clip that does not mark every planned beat; the beats it marked are saved in
    checks/probe.json for the sync report.

074 [MODIFIED] app/run_steps.py — TASK.json / TASK.md beats
    TASK.json carries the number of beats; the BEATS block in TASK.md tells the builder to call `self.beat(n)`
    where beat n starts.

075 [MODIFIED] app/run_steps.py — shared scene rendering
    The final command's nested render became module functions `render_scene_sections()` (jailed section render

076 [ADDED] app/run_steps.py — `preview` command
    `text-2-shorts preview <run> sNN` renders the whole scene (with its opening transition) at 720p30 with its
    audio → scenes/sNN/preview.mp4, plus contact sheets (one frame every 2 s) for the video-critic.

077 [ADDED] app/run_steps.py — `sync_report()` → scenes/sNN/sync.json
    The changes-made document: per beat, when the voice says it vs when the animation marks it (offset), whether
    each clip's audio fits its video, and each builder's CHANGES.md; tolerance `SYNC_TOLERANCE_SECONDS = 0.35`.

078 [ADDED] app/run_steps.py — CP3 requires preview, sync and video critique
    `preview_problems()` plus the video critique are required at CP3 and listed in status: a current preview,
    speech in sync with the animation, and a passing (or round-3) video critique.

079 [ADDED] app/run_steps.py — `doc` command
    `text-2-shorts doc Name1,Name2 [--topics …]` prints Manim 0.20.1 API cards from the installed package, so the
    planner and the critics check names instead of guessing.

080 [MODIFIED] app/clip_gates.py — drafts at 720p30
    `./check render` renders the clip's draft at 1280×720, 30 fps (was 854×480, 15 fps); `DRAFT_QUALITY` in

PART 3 — 0.9.0: option B — a deterministic driver, scenes in series, a scene's clips in parallel
-------------------------------------------------------------------------------------------------

104 [ADDED] app/run_steps.py — `next_actions()` and the `next` command
    `text-2-shorts next <run> [--json]` returns the exact next batch: each action says who does it (write,
    subagent, command, ask the user), its target and the files to read by path, and whether the batch is parallel.

105 [MODIFIED] app/run_steps.py — session start shows the next batch
    The SessionStart hook prints the status followed by "NEXT BATCH", so a resumed session knows exactly what to do
    without re-reading files.

106 [ADDED] app/run_steps.py — `critique_state()`
    Classifies a scene's critique as missing, stale, revise, exhausted or done, so the driver knows whether to call
    the critic, ask for a refactor first, or move on to the checkpoint.

107 [ADDED] tools/scene_harness.py — `self.entry(name, make)`
    In the composed scene it returns the object the previous clip left; when a clip runs alone it builds the object
    with `make()` and shows it. This is what lets every clip of a scene be built and checked independently.

108 [ADDED] tools/validate_manim_code.py — `ENTRY_NOT_STANDALONE` and entry-call contracts
    Every entry object must be taken with `self.entry(...)`; a `self.entry` call for a name outside the entry
    contract is a CONTRACT_READ error; `entry` joins the known project scene methods.
